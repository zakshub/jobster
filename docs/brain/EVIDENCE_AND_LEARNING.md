# Evidence and Learning

## Purpose

Jobster must become more useful as Zak gives feedback.

It must not become more confident merely because more text has accumulated.

## Evidence classes

Adapted from ZOS:

1. Repeated observable behavior.
2. Created artifacts.
3. Process evidence.
4. Professional record.
5. Explicit correction.
6. Self description.
7. Inference.
8. Hypothesis.
9. Unknown.

## Capability confidence

Use:

high
medium
low
unknown

## Capability labels

Use:

core
strong

not_claimed

## Conflict rule

When evidence conflicts, prefer:

repeated behavior
then artifacts
then process evidence
then professional record
then self description

Explicit user correction remains important and is stored with provenance.

Do not force false consistency.

## Preference learning

Feedback examples:

interesting
boring
too generic
would apply
would never apply
salary too low
good company bad role
can learn this
outside my direction
worth stretching for
not worth stretching for

Each feedback event should be stored as evidence linked to the evaluated job and previous CareerBrain decision.

## Model update rule

Important CareerBrain changes are proposed, not silently mutated.

A proposed update contains:

1. Current value.
2. Proposed value.
3. Reason.
4. Supporting evidence.
5. Contradictory evidence.
6. Previous confidence.
7. Proposed confidence.
8. Alternative explanations.
9. Status.

## Learning loop

job
then CareerBrain decision
then Zak reaction
then outcome
then model update proposal
then approved model update

## Outcome learning

Later, Jobster should learn from:

1. Recruiter response.
2. Interview.
3. Rejection.
4. Offer.
5. Negotiation result.
6. Post interview interest.
7. Differences between posting and actual role.

Outcome evidence updates strategy carefully and never converts correlation into certainty.
