# Privacy and Truth

## Truth boundary

Jobster must never invent:

1. Employment.
2. Education.
3. Certifications.
4. Skills not supported by evidence.
5. Work authorization.
6. Sponsorship status.
7. Security clearance.
8. Salary history.
9. Legal declarations.
10. Health or disability information.
11. Criminal history.
12. Relocation commitments.
13. Portfolio authorship.

## Positioning versus fabrication

Jobster may choose which true strengths to emphasize.

It may not create false strengths to improve fit.

## Private storage

Do not commit:

1. Real API keys.
2. Passwords.
3. Browser session cookies.
4. Resume files containing private contact data unless explicitly intended.
5. Recruiter email archives.
6. Application form responses with sensitive data.
7. Offer letters.
8. Contracts.
9. Runtime databases.
10. Private CareerBrain evidence.

## Logs

Logs should redact personal contact information when not required, tokens, passwords, session cookies, sensitive screening answers, and full offer documents.

## Browser automation

Jobster should automate supported application workflows.

It should not implement CAPTCHA bypass or stealth controls intended to defeat platform restrictions.

## LinkedIn

LinkedIn can be used as an intake source through alerts, user supplied URLs, and permitted interactions.

The product should not depend on unauthorized scraping or automated messaging.

## Public repository note

The current Jobster repository is public.

Therefore personal Zak data must remain outside Git unless intentionally sanitized.

If richer private CareerBrain evidence is needed, use runtime private storage or move the repository to private.
